# Pin htmx 4.0.0 and stop it swapping error responses

## Why

`base.jinja` loads a beta of htmx 4 (`4.0.0-beta2`). By default, htmx 4 swaps **every response except
204 and 304** (`config.noSwap = [204, 304]`), so a 4xx or 5xx body lands in the target like a 200's
would. htmx 2 didn't do that, and the app was written for it. CLAUDE.md says "htmx doesn't swap error
responses", and the two refusal handlers (`handle_forbidden`, `handle_blocked`) and the 422 rule rely
on it. So across the whole app, a polled fragment that gets a 403 or 404 shows the server's raw JSON,
or the whole 403 page, where its content should be. `exercise.js` works around this for the exercise
pages only (`[data-swap-guard]`); everything else is exposed.

While checking the beta against 4.0.0, a second bug turned up: **all 15 `hx-disabled-elt` attributes
do nothing**. htmx 4 renamed the attribute to `hx-disable` (htmx 2's `hx-disable` became `hx-ignore`),
and neither the beta2 nor the 4.0.0 file contains the string `disabled-elt`. So no button or input is
disabled while its request is in flight, and a double-click on "Enroll", "Block" or a role `<select>`
sends two requests.

## Decision

Stay on the htmx 4 line, at the **stable 4.0.0** (released 2026-08-28; npm `next`), and bring back the
htmx 2 rule through htmx's own configuration instead of rewriting the app around htmx 4's default.
Going back to 2.0.11 was considered and rejected (see *Rejected*).

## How htmx 4.0.0 handles a response (read from `dist/htmx.js`, 4.0.0)

Every step below depends on these details:

1. **Headers come first.** After the fetch, `HX-Redirect` / `HX-Refresh` / `HX-Location` are handled
   (`#handleHeadersAndMaybeReturnEarly`) *before* any status check. The 204 + `HX-Redirect` from
   `handle_not_authenticated` is unaffected by anything here.
2. **Then the status.** `#handleStatusCodes` tries the code in three forms, exact (`"403"`), tens
   (`"40x"`) and hundreds (`"4xx"`), in that order. For each form it first looks in `config.noSwap`
   (a match sets `ctx.swap = "none"`), then for an `hx-status:<form>` attribute on the source element.
   So an element-level `hx-status:403` beats a global `"4xx"`, but `hx-status:4xx` does **not**.
3. **`swap()` still runs on a `none` swap.** The body is parsed, any `hx-swap-oob` elements in it
   **are** swapped, `htmx:before:swap` and `htmx:after:swap` fire, and then
   **`document.title` is set from the body's `<title>`** if it has one. Only the main-target insertion
   is skipped (`#insertContent` returns on `none`).
4. **Config is read once, at construction**, from `<meta name="htmx-config" content="…">`. So the
   meta tag must come **before** the `<script>`. The content may be JSON. `HCON.merge` **replaces**
   arrays rather than merging them, so the value has to list 204 and 304 itself.

Point 3 means `noSwap` alone isn't enough. A polled fragment refused by `handle_forbidden` or
`handle_blocked` gets a full page that extends `base.jinja`, so the tab title would still change to
"Cocco - <refusal>" every poll. Those two handlers have to stop sending a page to htmx (step 3).
FastAPI's default `{"detail": …}` JSON for a plain 404 has no title and no OOB, so it is harmless
once it isn't swapped.

## Steps

1. **Pin 4.0.0 in `base.jinja`.** Replace the script tag with the explicit file path, so the
   integrity hash is tied to a file and not to whatever jsdelivr serves as the package default:
   - `src="https://cdn.jsdelivr.net/npm/htmx.org@4.0.0/dist/htmx.min.js"`
   - `integrity="sha384-BvJpBiO8Kh31EqtJe5DRIeWrHWnCGkwytKs9NKFi86Hhw96dEqdEMzZDeK9iEGTc"`
     (computed 2026-10-22 with `curl … | openssl dgst -sha384 -binary | openssl base64 -A`; recompute
     it during implementation and check the two match)
   - keep `crossorigin="anonymous"`.

2. **Configure `noSwap` in `base.jinja`.** Add, directly above the script tag:
   `<meta name="htmx-config" content='{"noSwap": [204, 304, "4xx", "5xx"]}'>`, with a short Jinja
   comment covering three points: it restores htmx 2's rule that CLAUDE.md's htmx rules assume; it
   has to precede the script; and it must name 204/304 because the merge replaces the array.
   Every page loads htmx through `base.jinja` and nothing else does, so this one tag covers the app.

3. **Make refusals bodiless for htmx.** In `cocco/web/access.py`, `handle_forbidden` and
   `handle_blocked` branch on `HX-Request: true` (as `handle_not_authenticated` already does) and
   answer a bare `Response(status_code=403)`, without rendering the template. Reason (point 3 above):
   a page body would still set `document.title`, and the body is never shown anyway. Update both
   docstrings: the existing sentence in `handle_blocked` ("htmx does not swap the body of an error
   response") becomes true again, and now has to say that it's true *because of* the `noSwap`
   setting, and why the body is dropped as well.

4. **Rename `hx-disabled-elt` → `hx-disable`** at all 15 sites, values unchanged (`find button`,
   `find input`, `find select`; htmx 4's `#findAllExt` supports `find`):
   `_course-card.jinja:64`, `course-people.jinja:37`, `f-profile-identity.jinja:42,55,68`,
   `challenge-edit.jinja:116`, `f-enroll.jinja:37,60`, `course-edit.jinja:179`,
   `f-users.jinja:101,116,138`, `f-course-people.jinja:77,109`, `admin.jinja:36`.
   Check first that no template already uses `hx-disable` in htmx 2's sense (none today) and that
   none uses `hx-ignore`.

5. **Audit for anything that relies on an error body being swapped.** The app has run on beta2 since
   it began (`5643503`), so a feature may quietly depend on htmx 4's default. Check:
   - every `hx-*` route in `cocco/web/` (not `api.py`) that can return a 4xx with a body the user is
     meant to read. CLAUDE.md says those should be 200 + alert; list any that aren't and convert them
     to the 200 + alert shape;
   - the tests that send `HX-Request` and assert on a 4xx's body;
   - any `hx-status:` attribute (none today).

   Record what turns up in *Outcome*. If nothing does, say so.

6. **Leave `exercise.js`'s swap guard in place; fix its comment.** It still works under `noSwap`:
   `htmx:before:swap` fires on a `none` swap with `ctx.response.status` set (point 3), so the guard
   still freezes a polling strip and shows its "stopped updating" line. That line is now the only
   sign of a lost poll anywhere in the app, so it's worth keeping. Its `preventDefault()` becomes
   belt-and-braces. Rewrite lines 23–29: the reason is no longer "htmx 4 swaps error bodies" but
   "a refused poll would otherwise keep firing silently, with nothing on screen to say so".
   Don't spread the guard to other pages in this plan (see *Not in scope*).

7. **Docs.**
   - `CLAUDE.md`, *htmx rules*: the first two bullets stay true, but point them at the
     `noSwap` meta in `base.jinja` as the reason ("htmx is configured not to swap error responses"),
     so the next version bump can't silently undo them. Mention `hx-disable` (not `hx-disabled-elt`)
     as the in-flight guard if the bullets name it.
   - `.claude/rules/authorization.md:30`: "htmx ignores error bodies" → configured not to swap
     them, and refusals to htmx requests are bodiless (step 3).
   - `.claude/rules/frontend.md`: one bullet that htmx is pinned to 4.0.0 by file path + SRI, and
     that `noSwap` lives in the meta tag above it. A version bump means recomputing the hash and
     rereading the migration guide's swap and inheritance sections.
   - `.claude/rules/exercises.md:163` and `cocco/web/exercise_sets.py:523`: "the htmx 4 this app
     loads has no special case for 286" stays true for 4.0.0; reword "4.x" to "4.0.0" only if the
     surrounding text mentions the beta. No other change.
   - Leave the finished plans (`interactive-exercises`, etc.) alone: they're history.

## Tests

- **Template lint** (in `cocco/test_main.py`, beside the route-order test): no file under
  `cocco/templates/` contains `hx-disabled-elt`. That's the one regression a future copy-paste from
  htmx 2 docs would bring back silently.
- **Config is rendered:** a page (e.g. `/login`) contains the `htmx-config` meta with `"4xx"` and
  `"5xx"`, and it appears before the htmx `<script>` in the response text.
- **Refusals to htmx are bodiless:** with `HX-Request: true`, a `Forbidden` route and a blocked
  account each answer 403 with an empty body; without the header, they still render the page (the
  existing tests in `test_auth_routes.py` / `test_admin_routes.py` already cover the second half;
  add the htmx half next to them).
- `uv run pytest -m "not integration"` passes.

## Verification (by hand, in a browser)

The app has no JS test harness, so htmx's behaviour itself is checked by hand, `just web` + `just judge`:

1. A submission page polling `queued` → done: unchanged.
2. Unenroll a student (second browser) while their submission page polls: the fragment stays as it
   was, no JSON and no 403 page appear, **the tab title doesn't change**, and the poll's 403s show in
   the network panel.
3. Delete an exercise session while a student's strip polls: the `exercise.js` "stopped updating"
   line still appears.
4. Click "Enroll" and a people-page role `<select>`: the control is disabled until the response
   arrives (throttle the network to see it).
5. Sign out in another tab while a page polls: the 204 + `HX-Redirect` still navigates to login.
6. Devtools: `htmx.config.noSwap` is `[204, 304, "4xx", "5xx"]`, and the script came from
   `@4.0.0/dist/htmx.min.js` with no SRI error in the console.

## Not in scope

- **A general "lost contact" indicator** for every polled fragment (what `[data-swap-guard]` does
  for exercises). With `noSwap`, a refused poll freezes silently, which is what the rest of the app
  was written to expect. Worth its own plan if wanted.
- **Vendoring htmx under `cocco/static/`** like CodeMirror. The SRI-pinned CDN URL is already
  immutable; vendoring is about offline/CDN independence, a separate decision.
- **Other htmx 4 changes** that don't affect this app today: explicit inheritance (`:inherited`;
  `f-courses.jinja`'s "inherited" is Jinja context, not htmx), OOB now swapping *after* the main
  content, `hx-sync` as the only queueing control, `HX-Trigger` request header → `HX-Source`. None
  are used in a way the 4.0.0 behaviour breaks; the audit in step 5 should confirm in passing that
  no Python reads the `HX-Trigger` request header.

## Rejected

- **Going back to htmx 2.0.11.** It fixes the error swapping and `hx-disabled-elt` without any edits,
  but brings back implicit attribute inheritance, so every ancestor's `hx-target` / `hx-confirm` /
  `hx-swap` would need auditing across ~65 swap sites. `exercise.js`'s guard would need rewriting for
  `htmx:beforeSwap` and htmx 2's event detail, and the "no special case for 286" notes would become
  wrong. That's a larger diff, onto the older line.
- **`hx-status:4xx="swap:none"` per element** instead of the global config. It's opt-in, so every
  new fragment is exposed until someone remembers it, the same failure as today.
- **Setting `htmx.config.noSwap` from an inline script** after the htmx script. It works, but the
  meta tag is the documented route, is read at construction (so no request can slip in before the
  setting applies), and keeps `base.jinja` free of inline JS.
- **Leaving the refusal handlers as they are** and relying on `noSwap`. The title change (point 3) and
  any future `hx-swap-oob` in `base.jinja`'s navbar would still reach the page.
